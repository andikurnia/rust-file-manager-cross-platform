# Plan: macOS Finder Clone for Linux (Wayland) — GTK4 + Rust

## Goal

Build a native macOS Finder clone in Rust using GTK4/libadwaita, targeting Linux Wayland first, packaged as `.deb` (Debian/Ubuntu) and `.rpm` (RHEL/Fedora).

## Current Context / Assumptions

- **Workspace**: `/home/kndi/Documents/PRSNL/UBUNTU/finder-linux/` — empty directory, greenfield project.
- **OS**: Ubuntu 26.04 LTS, Wayland session (`wayland-0`), GNOME desktop.
- **GPU**: Intel Arc Graphics (Meteor Lake) — hardware-accelerated rendering available.
- **Toolchain**: Rust 1.97.1, cargo 1.97.1, dpkg-deb + dpkg-dev installed, rpm tools installable via apt.
- **GTK4 runtime**: Already installed (`libgtk-4-1` 4.22.4, `libadwaita-1-0` 1.9.1). Dev headers (`libgtk-4-dev`, `libadwaita-1-dev`) need `apt install`.
- **Build tools**: `meson` and `ninja-build` need `apt install`. Not required for cargo builds but useful for system integration.
- **No Flatpak** — user explicitly rejected Flatpak. Distribution via `.deb` and `.rpm` only.
- **No existing code** — every file is created from scratch.
- **User preference**: Concise, no fluff. TDD cycle per task. Frequent commits. DRY, YAGNI.

## Architecture / Proposed Approach

A single-binary Rust application using GTK4 + libadwaita for the UI layer, `gio` for async file operations and volume monitoring, and `std::path` for path handling. The app follows a simple MVC pattern: `FileItem` models feed into GTK4 view widgets (`GtkColumnView` for list, `GtkGridView` for icons), with a `NavigationState` managing back/forward history. Packaging uses `cargo-deb` for `.deb` and a manual `rpmbuild` spec for `.rpm`, both producing a standalone binary + desktop file + icon.

```rust
use std::path::PathBuf;

#[derive(Debug, Clone)]
pub struct FileItem {
    pub name: String,
    pub path: PathBuf,
    pub is_dir: bool,
    pub size: u64,
    pub modified: i64,
    pub mime_type: String,
}

impl FileItem {
    pub fn from_gio_file(file: &gio::File, info: &gio::FileInfo) -> Self {
        let name = info.name().to_string_lossy().to_string();
        let path = file.path().unwrap_or_else(|| PathBuf::from(&name));
        let is_dir = info.file_type() == gio::FileType::Directory;
        let size = if is_dir { 0 } else { info.size() as u64 };
        let modified = info.modification_date_time().map(|dt| dt.to_unix()).unwrap_or(0);
        let mime_type = info.content_type().unwrap_or_else(|| "application/octet-stream".into());
        let mime_type = mime_type.to_string();

        Self { name, path, is_dir, size, modified, mime_type }
    }

    pub fn icon_name(&self) -> String {
        if self.is_dir {
            return "folder".to_string();
        }
        match self.mime_type.as_str() {
            m if m.starts_with("image/") => "image-x-generic",
            m if m.starts_with("text/") => "text-x-generic",
            m if m.starts_with("video/") => "video-x-generic",
            m if m.starts_with("audio/") => "audio-x-generic",
            m if m.starts_with("application/pdf") => "application-pdf",
            _ => "application-x-executable",
        }
        .to_string()
    }
}
```

```rust
pub async fn list_directory(path: &std::path::Path) -> Result<Vec<FileItem>, glib::Error> {
    let dir = gio::File::for_path(path);
    let enumerator = dir
        .enumerate_children_async(
            "standard::*,time::modified",
            gio::FileQueryInfoFlags::NONE,
            glib::Priority::DEFAULT,
            None::<&gio::Cancellable>,
        )
        .await?;

    let mut items = Vec::new();
    while let Some(infos) = enumerator.next_files_async(100, glib::Priority::DEFAULT, None::<&gio::Cancellable>).await? {
        for info in infos {
            let child = dir.child(info.name());
            items.push(FileItem::from_gio_file(&child, &info));
        }
    }
    Ok(items)
}
```

#### Task 1.3: Create NavigationState for back/forward history

**What**: Track navigation history.

**File**: `src/app.rs` — create:

```rust
use std::path::PathBuf;

#[derive(Debug, Clone)]
pub struct NavigationState {
    pub current: PathBuf,
    pub back_stack: Vec<PathBuf>,
    pub forward_stack: Vec<PathBuf>,
}

impl NavigationState {
    pub fn new(initial: PathBuf) -> Self {
        Self {
            current: initial,
            back_stack: Vec::new(),
            forward_stack: Vec::new(),
        }
    }

    pub fn navigate_to(&mut self, path: PathBuf) {
        self.back_stack.push(self.current.clone());
        self.current = path;
        self.forward_stack.clear();
    }

    pub fn go_back(&mut self) -> Option<PathBuf> {
        if let Some(prev) = self.back_stack.pop() {
            self.forward_stack.push(self.current.clone());
            self.current = prev.clone();
            Some(prev)
        } else {
            None
        }
    }

    pub fn go_forward(&mut self) -> Option<PathBuf> {
        if let Some(next) = self.forward_stack.pop() {
            self.back_stack.push(self.current.clone());
            self.current = next.clone();
            Some(next)
        } else {
            None
        }
    }

    pub fn can_go_back(&self) -> bool {
        !self.back_stack.is_empty()
    }

    pub fn can_go_forward(&self) -> bool {
        !self.forward_stack.is_empty()
    }
}
```

```rust
pub struct IconView {

impl IconView {

        widget.set_homogeneous(true);
        widget.set_max_children_per_line(10);

        widget.set_margin_top(12);
        widget.set_margin_bottom(12);
        widget.set_margin_start(12);

    pub fn populate(&self, items: &[FileItem]) {
        while let Some(child) = self.widget.first_child() {
            self.widget.remove(&child);

        for item in items {

    fn create_item_widget(&self, item: &FileItem) -> FlowBoxChild {
```

## Risks, Tradeoffs, and Open Questions

### Risks

| Risk | Impact | Mitigation |
|---|---|---|
| GTK4-rs API instability | Medium | Pin to specific crate versions; GTK4 4.22 is stable |
| Async file ops blocking UI | High | All file I/O uses `gio` async APIs; never call sync I/O on main thread |
| Large directory performance | Medium | Lazy loading with pagination; defer thumbnails to later phase |
| Cross-platform path handling | Low | Use `std::path::PathBuf` + `gio::File` throughout |
| RPM build requires rpmbuild | Low | Document `sudo apt install rpm rpmbuild` in README |

### Tradeoffs

- **GTK4 over raw Wayland**: GTK4 handles Wayland protocol details, input events, and rendering. Raw Wayland would be 10x the work for no user-visible benefit.
- **libadwaita over plain GTK4**: libadwaita provides modern GNOME-style widgets (header bars, sidebar styling) that match Finder's aesthetic. Slight dependency cost, significant UX gain.
- **.deb + .rpm over Flatpak**: Native packages integrate with the system (theming, file associations, desktop search). No sandboxing overhead. User explicitly requested this.
- **Single binary over library**: Simpler packaging, no shared library versioning issues.

### Open Questions

1. **Column view (Miller columns)**: This is the signature Finder view. Should it be in v1 or deferred? It's the hardest view to implement well.
2. **Thumbnail generation**: Should we generate thumbnails for images/videos in v1, or use generic icons only?
3. **Search**: Should v1 include live name filtering only, or full content search?
4. **Drag-and-drop**: Should v1 support drag-and-drop file operations, or is context-menu-only sufficient?
5. **Settings persistence**: Should window size/view mode be saved across sessions in v1?
6. **Trash integration**: Should we implement freedesktop.org Trash spec, or just use `gio::File::trash()`?
7. **Multi-selection**: Should v1 support selecting multiple files, or single-file operations only?
